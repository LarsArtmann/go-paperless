Accepted deviations (documented)

The model is a deliberate two-layer design: unexported *Payload structs mirror the Paperless-ngx serializers exactly (including their pointer-for-absent-key quirks), and every boundary function translates them into stable public types (TaskOutcome, DocumentMeta, StoragePath, CustomFieldValue). The wire never leaks; the public surface never chases server refactors.

02The Model That Works

Core entities: Document (by checksum), Task (async consumption), NamedObject (tag/correspondent/type/field/path — one find/create/ensure seam), Capability (server-shape probe). The invariants that must always hold are enforced where they are cheap and honest:

// A client cannot exist unconfigured:
func New(baseURL, token string, opts ...Option) (*Client, error)

// An outcome cannot be mistaken for a failure when the server refused a duplicate:
func (o TaskOutcome) Duplicate() (documentID int64, inTrash, refused bool)

// Unknown future statuses can never be treated as final:
func (s TaskStatus) Terminal() bool // success | failure only

04Decision Log (with rejected alternatives)

1

Rejected: branded ID types

type DocumentID int would buy compile-time distinction at the cost of breaking bank-sync's drop-in consumption — the explicit product constraint in AGENTS.md. Accepted deviation, documented.

2

Rejected: public Page[T] envelope type

Consumers never see pages — every public list method returns the full, cap-bounded collection. Generics went where the duplication was (the walk), not where fashion points.

3

Kept: pointer fields for PATCH and free-form dicts

Replacing them with sum types would invent a second representation of HTTP semantics that every caller must translate. The pointer IS the protocol here.
