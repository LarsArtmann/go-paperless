01Findings

The catalog’s core promise breaks under retry exhaustion

ERROR_CODES.md promises consumers can switch on paperless.* codes. But when WithRetry is enabled and attempts exhaust, the surfaced code becomes retry.exhausted (family Infrastructure) — the paperless code and its Transient family are buried one cause deeper, exactly in the persistent-429 scenario where a consumer needs them most.

Document + test the real surface, then fix upstream

Pin the exhausted/canceled/deadline surface with tests, document the retry.* outcomes in the catalog, fix the two doc lies (request_failed family, the “every error” header), and evaluate a go-retry option that keeps the last attempt’s classification outermost.

02Issue Cards

Contract break

Retry exhaustion replaces the paperless code and flips the family

client.go:1790-1816 · go-retry v0.8.0 retry.go:123

go-retry wraps exhaustion as WrapInfrastructure(retry.ErrExhausted, "retry.exhausted") with the last attempt error as cause. Per ADR 0002, Code(err)/Classify(err) return the outermost classification — so a rate-limited upload that survives all attempts surfaces as retry.exhausted / Infrastructure, not paperless.rate_limited / Transient. errors.Is/errors.AsType still reach the cause, but every code-switching consumer breaks. No SDK test pins this surface; the catalog does not mention it.

Fix Pin the exhausted surface with a test, document the retry.* outcomes in ERROR_CODES.md, and evaluate surfacing the last attempt’s code upstream (keep the fail-closed Infrastructure family for nesting).
Doc lie

“Every error carries a paperless.* code” is false three ways

docs/ERROR_CODES.md:3 · client.go:140,313 · go-retry retry.go:23-59

The catalog header overclaims: ErrInvalidConfig is a bare errors.New sentinel (no code, no family), and the three retry-terminal outcomes carry retry.* codes. The doc-drift test only checks one direction — that every constructed paperless.* code has a row; nothing checks the reverse (SDK errors without a code or row).

Doc drift

request_failed family: docs say Infrastructure, code says Transient

docs/ERROR_CODES.md:38 vs client.go:1863

The code is load-bearing: the default retry predicate retries only Transient errors, and the same catalog row says “Retryable: yes” — network failures only retry because the constructor is WrapTransient. The doc row is stale and wrong.

Fix One-word doc fix: family Transient. (Deciding network errors are Infrastructure and never retry would be a bigger design change.)
Misclassification

3xx responses classify as server_error / Transient

client.go:2054-2072 (classifyStatus)

The switch has branches for 401/403, 429, and 4xx; everything else — including redirects from a reverse proxy or an http→https upgrade — falls into the 5xx default: paperless.server_error, family Transient, i.e. “retry the redirect”.

Inconsistency

Cancellation surface changes shape with WithRetry

client.go:1861-1866 vs go-retry retry.go:214-218

Same failure, different surface: without retry, a canceled request returns paperless.request_failed (Transient) wrapping context.Canceled; with retry, the loop’s backoff check converts it to retry.canceled (Infrastructure). Both unwrap to context.Canceled, but code-switching consumers see two different codes for one condition.

Strengths

+
Classification at the source of failure classifyStatus, decode guards, validation guards; no unclassified construction leaks — the erraudit gate is green.
+
Mechanical catalog gate TestErrorCodesAreDocumented resolves even the kind-parameterized constructor sites; a non-literal kind argument fails the test.
+
Structured context everywhere status, path, body snippet, and a body_read_error key that explains a truncated snippet instead of leaving it silent.
+
Retry-After bridging with tests 429/503 hints parsed (seconds and HTTP-date), delay function bridged, family stays Transient through call-site wraps.
+
Retry body replay The body is snapshotted once and replayed byte-for-byte per attempt; no consumed-reader bug (tested).
+
Rejections never retried The default predicate is Transient-only and TestWithRetryNeverRetriesRejections pins exactly one request.
+
Defensive decode fallback GetTask tolerates the bare-array shape and wraps the envelope failure, with a reasoned comment on why.
+
Debuggable poll abandonment task_poll_abandoned wraps context.DeadlineExceeded and keeps the last poll error attached.
+
Family assertions across the suite 20+ tests assert Classify/Code values, not just error non-nil — the family contract is executable.

03Improvement Plan

1

Fix the two catalog lies

Correct the request_failed family cell to Transient; scope the header claim; add a Retry-outcomes section documenting retry.exhausted / retry.canceled / retry.deadline and the bare sentinel. Docs only.

2

Pin the surfaces with tests

Assert code+family after retry exhaustion, cancellation with and without WithRetry, and the 3xx classification — before changing any of them.

3

Add the classifyStatus 3xx branch

Classify redirects as Rejection with the Location header in context, instead of retryable server_error.

4

Evaluate the upstream option

A go-retry option that keeps the last attempt’s code outermost on exhaustion while the family stays Infrastructure for fail-closed nesting. Verify against go-retry source before filing.

5

Optional: code the sentinel

Return a coded wrap of ErrInvalidConfig (paperless.invalid_config, Rejection) — errors.Is stays matchable and new codes are contract-legal.
